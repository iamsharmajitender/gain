# Blueprints

Reference architectures, full operating models for a capability, not a one-off essay. One G.A.I.N subject maps to one playbook series. Governance has two blueprints (operating and runtime) because the audience splits; it is still one G.A.I.N subject.

## 1. Evaluation: eight planes

| | |
| --- | --- |
| **[G.A.I.N Evaluation](/frameworks/gain-evaluation)** | Principles, ownership, and pillar mapping: published |
| **[Eval Blueprint](/blueprints/evaluation-blueprint)** | Sources, scorers, modes, gates, eight planes: draft |

Playbooks: [Evaluation](/playbooks/evaluation). Planes: ① Input · ② Data · ③ Context · ④ Reasoning · ⑤ Tool · ⑥ Memory · ⑦ Action · ⑧ Outcome.

## 2. Agents: intent, orchestration, manifests

Intent at ingress, orchestration in the loop, versioned manifests (pinned tools, schemas only), four autonomy patterns on the route. Model endpoint selection is the [LLM Blueprint](/blueprints/llm-blueprint). PEP is [Governance](/blueprints/governance/runtime). MCP is transport only.

| | |
| --- | --- |
| **[G.A.I.N Agents](/frameworks/gain-agents)** | Principles, policy gate, orchestration: published |
| **[Agents Blueprint](/blueprints/agents-blueprint)** | Intent, orchestration, manifests, Pattern 0-3: draft |

Playbooks: [Agents](/playbooks/agents) (Plane ① [Intent router](/playbooks/agents/intent-router) · Plane ② [Orchestration](/playbooks/agents/orchestration) including [Memory](/playbooks/agents/orchestration/memory) · [Manifests](/playbooks/agents/manifests/manifest-registry)). Patterns: 0 Single inference · 1 Autonomous loop · 2 Deterministic · 3 Guided hybrid.

## 4. Governance: operating model and runtime

Two blueprints, one G.A.I.N subject. Operating is the estate control system. Runtime is PGAR on the request path. PGAR gates side effects. It does not own RAG corpora, tool manifests, or the memory store.
